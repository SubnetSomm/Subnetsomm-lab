# Problem Analysis

Project 1 : Analyze the Problem The problem is that I am a freelance designer with less-than-ideal spending habits. I need to be able to keep track of my income and expenses ,  especially if I’m trying to make a profit, let alone break even. Currently, I’m tracking these expenses manually through notes or spreadsheets, and it’s both time-consuming and  error-prone . Automating this process will help me maintain accurate totals and make it easier to spot patterns in how I earn and spend money over time. The goal of this program is to help users like me log income and expenses, organize them by category, and generate a summary that shows whether I’m operating at a profit or loss for the month. I should be able to come home after a day’s work and have my program ask me for all the transactions that happened during the day. Even if I spent most of my day chain-drinking coffee after coffee just to make it through my projects and emails from each client, the program should make it easy to capture those details without much thought. It should have at least two fields for me to enter ,  a dollar amount and the category of the transaction ,  as well as an automatic date entry for each input. For example, if I bought three coffees throughout a stressful day, I should be able to enter the total I spent ($9) and shamelessly type “coffee” as the category. That way, the program can track my spending habits and show me how much of my income is going toward caffeine. Considering that I’m a visual person, I would eventually like the program to operate in a GUI format. A GUI would allow me not only to input the needed data but also to view  a history  of my transactions and see category totals and an overall balance  at a glance . Although I like to enter data at the end of my day, the program should ideally store information in the cloud so I can access it whether I’m home or traveling for a client meeting. I should be able to securely log in to the program’s portal, enter my credentials, and see my data instantly. Since this is sensitive financial information (and, frankly, no one needs to know how much coffee I buy in a week), the service should be as secure as possible so only I can view, enter, and export my expense reports. However, recognizing my current experience level, I’ll start with a console-based version that stores data locally. This keeps the project realistic and within my current programming abilities while laying the groundwork for future improvements. Later enhancements could include the GUI interface, secure login, and cloud connectivity once I learn more about file handling and user authentication. When I open the program, it should immediately prompt me to begin entering transactions ,  no distractions, just straight to the point. The inputs it requests will include the  dollar amount ,  transaction type (income or expense) ,  category , and an  automatic date entry . Once entered, the program will process that data by either adding or subtracting from the total balance and updating category totals. After each entry, it will ask if I want to add another transaction, creating a simple loop until I’m done. Once I finish, the program should display a clear summary showing my updated balance, each category total, and a motivational message ,  either encouraging me to  buy a sweet treat  or gently reminding me to rein in my spending (preferably with humor). Behind the scenes, the logic will rely on  sequence structures  for input and calculation,  dual-alternative decision structures  to separate income from expenses, and a  loop  that allows repeated entries until I choose to stop. The program’s flow will  move from top to bottom, returning to the input step each time a new transaction is entered. Conceptually, I imagine dividing the logic into small, manageable sections or “modules,” such as an  Input_Transaction  section for collecting  my spending  data, an  Update_Totals  section for calculations, and a  Display_Summary  section for showing results and  my motivational  messages. I’m still in the early phases of programming, and I know I’ll encounter more efficient logical and control structures as the semester continues. For now, this approach gives me a solid foundation ,  a simple, well-structured budget tracker that reflects real-world needs while staying within what I’ve learned so far. In the long run, I hope to develop it into a full application that genuinely helps me manage my spending habits. For now, though, this plan gets me started on the right track. Now, time for another coffee.
